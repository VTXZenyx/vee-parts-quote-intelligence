# Development backlog

The local product uses synthetic data. Work in the following order unless a failing workflow or a security defect takes priority. Each row describes the evidence needed to close the task.

| Priority | Task | Acceptance criteria |
| --- | --- | --- |
| P1 | Run an observed sales-desk demonstration with one NZ distributor | Ask an owner and an estimator to complete the cylinder and shortage cases from the dashboard with synthetic data. Record where they hesitate, what evidence they need and whether they would pay for a narrowly scoped pilot. Agree one measurable pilot acceptance criterion. |
| P1 | Measure extraction on independently reviewed distributor enquiries | With appropriate data rights, label product lines, quantities, uncertainty and source spans. Compare deterministic and authorised live inference on the same held-out cases. Report unsafe recommendations, employee correction time and cost per enquiry before proposing a mailbox pilot. |
| P1 | Expand technical evidence and rule coverage | Add fixed examples for bearings, threaded fasteners and hydraulic fittings. For each, show the specific catalogue evidence for each governing attribute. A missing rating, mismatched standard or contradictory measurement blocks technical approval. A qualified industrial reviewer signs off the expected outcomes. |
| P1 | Establish a versioned, independently labelled evaluation set | Cover every scenario in TEST_PLAN.md. Store input, expected acceptable outcomes, sources, reviewer and dataset version. Report failures by category alongside a repeatable baseline. Identify synthetic or author-labelled cases separately. |
| P1 | Track evidence and edits across revisions | A reply or employee correction creates a traceable revision. Existing technical and quote approvals cannot be reused after a material change. Two concurrent edits produce one accepted revision and a visible conflict, with both attempts handled consistently. |
| P1 | Qualify the security boundary before real data | Authenticate employees, scope records and files to a business, and enforce role permissions on every read and write. Test two businesses and all roles across search, workspace, commercial records, attachments, exports and audit. Verify secret rotation, a redacted log sample and a restore drill. Obtain authorisation before accepting business records. |
| P2 | Process untrusted attachments in isolation | Allowlist types and sizes, verify content type, scan and parse with resource limits, and isolate storage and access. Test a synthetic wrong-type file, oversized document, parser timeout, duplicate and document containing instructions. Each failure leaves a recoverable enquiry with an accurate processing state. |
| P2 | Compare multimodal and hybrid retrieval providers | Benchmark exact/attribute retrieval against semantic and visual retrieval on the same reviewed items. Record model and catalogue versions, top-k recall, false exact matches, unsupported claims, latency and cost. Unreadable images and incompatible near-neighbours remain unresolved. Verify rights to images and manufacturer records. |
| P2 | Support partial and alternative multi-line quotations | Keep each request line and quantity identifiable through edits. Give each unavailable line a reason and require a new technical review for a substitute. Compare mixed-line totals with independent expected values and verify the employee can distinguish outstanding items. |
| P2 | Expand commercial records and document generation | Tests cover per-customer pricing, authorised discounts, validity dates, insufficient stock, unconfirmed lead time and unsupported currency. The printable or generated document identifies the approved revision, tax, terms and availability. Saving an edited revision requires fresh approval. |
| P2 | Add trustworthy delivery and inventory snapshots | Track connector provenance, effective time and freshness. A changed or expired stock or price record blocks finalisation until refreshed. An estimate displays as an estimate. Retry a failed import without duplicating or partially publishing a snapshot. |
| P2 | Implement approved outbound delivery | In a provider sandbox, bind named reviewer, recipient and content hash or immutable revision to a dispatch request. Rejections, edits and stale approvals cannot send. Exercise retry after an ambiguous provider response and reconcile to one provider message ID. Obtain separate authorisation for a real send. |
| P3 | Pilot authorised mailbox and ERP connectors | After the security criteria and source-specific authorisation, exercise least-privilege OAuth/API access, revocation, throttling, retry and reconciliation in the vendor sandbox. Record exact permissions and test evidence before a limited pilot. |
| P3 | Prepare multi-business operations | Rehearse database migration, interrupted worker recovery, tenant-scoped restore, audit access and an operator response to a failed import. Measure realistic workload, latency, availability and cost. Obtain approval before production deployment. |
| P3 | Evaluate employee usability and continuous improvement | Observe employees working representative cases with keyboard and small-screen layouts. Record time, corrections, unresolved decisions and actionable feedback. Re-run the fixed evaluation set before shipping retrieval or verification changes. |

See [ROADMAP.md](ROADMAP.md) for dependencies and [TEST_PLAN.md](TEST_PLAN.md) for verification requirements.
